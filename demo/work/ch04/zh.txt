版本控制系統（Version Control System，VCS）是現代軟體開發不可或缺的工具。
它讓團隊能夠追蹤變更、有效率地協作，並為專案保留一份可靠的歷史紀錄。
早期的系統如 RCS 與 CVS 雖然提供了基本的檔案版本管理功能，但僅限於集中式管理，使得分支（branching）與合併（merging）變得極為困難。
隨著專案規模不斷擴大，開發者經常為衝突（conflict）所苦，並耗費大量時間處理整合問題。

Subversion（SVN）作為改良方案應運而生，提供了更好的協作能力與更簡便的分支操作，但它仍然依賴中央伺服器。
這種集中式模式經常成為效能瓶頸，對於需要更快速、更彈性工作流程（workflow）的跨國分散式團隊而言尤其如此。

分散式系統的出現，尤其是 Git，徹底改變了軟體開發的實務做法。
Git 讓開發者可以離線工作、在本機進行 commit，並只在需要時才與其他人同步。
它也帶來了輕量級的分支、強大的合併功能，以及去中心化的工作流程，讓大規模協作變得更有效率。
如今，Git 已成為版本控制的業界標準（de facto standard），支撐著 GitHub 與 GitLab 等平台，並深刻影響全球現代團隊在軟體專案上的協作方式。
