互動教學，第九章第一步的判讀，也是整個課程的收尾。

第一，訪談做得很好。它分三輪、每輪四題，總共問了十二題，而且真的照提示詞的要求，專挑你可能沒想到的難點。例如：YouTube 對雲端機房的 IP 擋得很嚴，部署在 VPS 上常常下載失敗；字幕一換就截圖，一小時的影片會截出上千張；自動字幕會有前後重複、沒有標點的問題；以及截圖時間點，要在字幕開始的那一秒，還是區間中點。你選了區間中點，這正好就是書上九之三節最後修正的做法，它在訪談階段就先問出來了。

第二，規格文件選的技術是 FastAPI 加純 HTML 和 JavaScript，翻譯用 claude 減 p 走你的訂閱額度，不用 API 金鑰，這是它主動依照你的成本規則提出的選項。輸出有閱讀器、單檔 HTML、PDF 和 Markdown 四種。

第三，兩套規則的衝突。第一個模組 M1 照你的全域規則，跑了四輪驗證、兩輪審查。之後它主動問你要不要改用快速 demo 模式，你選了快速模式，後面的模組就快很多。這正是我們剛剛訂下的新規則。

第四，那個 session 其實做得比第一步多很多，一路做到 M7，包含 SQLite 工作佇列、即時進度、取消、歷史紀錄、匯出、Whisper 語音辨識備援和播放清單，等於把書上九之二到九之四的內容都做完了，還把 M2 交給 VPS 上的 Ralph 無人值守執行。

第五，有一個很值得記住的坑。這個 app 會在練習資料夾裡呼叫 claude 減 p 來翻譯字幕。早期每次呼叫，都會載入你的全域設定，結果全域的 Stop hook 跳出提醒有未提交的改動，模型就不翻譯，反而回答 git 的事。最終版在呼叫時加上不載入任何設定的參數，把它和你的全域設定隔開，才解決。以後寫程式呼叫 claude 減 p，記得要這樣隔離。

到這裡，第一章到第九章全部完成。跳過的有三個：兩個 Telegram 步驟，因為沒有 Bot Token；還有八之三的雙星號修正。以後想補可以再做。

最後一件事，那個 session 正在幫你寫實際操作網頁的說明，並寄到你的 Gmail。照著它跑一次完整流程，就可以親眼看到 YouTube 影片變成投影片。辛苦了。
