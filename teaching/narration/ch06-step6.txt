互動教學，第六章。先判讀第五步，再進行第六章最後一步。

第五步四個測試都照預期。它寫出來的 if 條件很直覺：Write 括號 星星斜線 tasks 點 json，Edit 也是一樣；Bash 那邊則是 Bash 括號 rm 空格星號，sudo 和 chmod 也各一條。

修改 tasks 點 json 時跳出詢問，你允許後才寫入。修改 todo 點 py 時沒有詢問，直接改好了。rm delete 點 txt 被擋下，delete 點 txt 還在。touch add 點 txt 正常建立。和舊電腦一樣。

它還多測了一個書上沒有的情況：用兩個 and 符號把 echo 和 rm 串在一起，rm 一樣被擋下。這是因為官方的比對規則會把串接的每一段指令分開檢查，所以藏在後面的危險指令也躲不掉。

被擋下的時候，它明確說：我不會改用 PowerShell 的 Remove Item 或 Python 去刪，這些都是可以繞過 hook 的方法，它選擇不用。

有一個小麻煩。它測試的時候建了一個 dummy hook test 點 txt，後來自己也刪不掉，因為 rm 被擋了。這個檔案還留在專案裡，等一下可以用驚嘆號 rm 自己刪掉。

接下來是第六步，對應六之五節的後半，也是第六章最後一步。前面的 hook 都是寫死的規則，這一步要讓判斷更聰明：先交給外部程式，再交給 Claude 模型自己判斷。

第一，清掉測試檔。輸入驚嘆號 rm 空格 dummy 減 hook 減 test 點 txt。

第二，貼上書上的提示詞，請它把剛剛的 Bash 規則改成執行一支 Python 程式。高風險的 rm 和 sudo 直接拒絕，中風險的 curl 和 mv 改成問你。因為是寫 Python 檔，你的全域規則會讓它派寫程式的 agent，這是正常的。

然後測兩個：幫我用 Bash 指令把 move 點 txt 搬移到 data 資料夾中，這個應該會問你。幫我用 Bash 指令把 move 點 txt 刪除，這個應該直接被擋。

第三，貼上書上的提示詞，改成 prompt 類型的 hook，讓 Claude 模型判斷這個指令安不安全。書上寫要用 Opus 四點七，但你現在的模型是 Opus 五點五，請它用目前可用的模型就好。接著再請它產生 prompt 的內容，規則是只要碰到點 env 這類重要檔案，就直接拒絕。

然後測兩個：幫我用 Bash 查看點 env 檔的內容，這個應該被擋。幫我用 Bash 查看 src 資料夾裡 todo 點 py 的內容，這個應該放行。

舊電腦有一個很特別的發現：prompt 型的 hook 擋下之後，Claude 最後的回覆是空的，什麼都沒說。看看這次會不會一樣。

做完之後請回報三件事。第一，外部程式放在哪裡，兩個測試結果。第二，prompt 型 hook 用了哪個模型，兩個測試結果。第三，被 prompt 型 hook 擋下時，Claude 最後有沒有說話。
