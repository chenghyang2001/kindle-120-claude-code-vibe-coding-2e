互動教學，第四章。先判讀第三步，再進行第四章最後一步。

第三步這次很順利。它建好審查員之後，自己就提醒你：這個 agent 和上一步那三個語言 agent，都是在這個對話開始之後才建立的，所以現在叫不到，要重新開一個對話。這也證實了上一步的推測，專案 agent 是在對話開始時載入的。你重開之後，它就真的用了 personal code reviewer。

和書上不同的是，書上只用一個審查員看兩份程式。這次主對話自己決定派出兩個審查員，同時各看一份，再由主對話整理成對照表。而且這台電腦有裝 Go，審查員真的編譯、執行，還補了測試，拿兩百組隨機資料和標準函式庫比對，兩邊排序結果全部正確。

評分結果，直接生成的版本是七分和七點五分，subagent 版本是八分和七點五分，也是幾乎打平，和舊電腦一樣。差別在細節。直接生成的版本有一個必須修正的問題：兩個檔案都放在同一個資料夾，又都叫 main，一起編譯會衝突。可是它的快速排序是原地排序，比較省記憶體。subagent 版本把檔案分開放，也不會改到傳進來的資料，但快速排序每一層都另外配置新的陣列，比較耗記憶體。

舊電腦抓到的那個問題，也就是遇到大量重複值會變慢，這次兩邊都沒有。因為這次的快速排序寫法和舊電腦不一樣，一邊取中間值當基準，一邊分成小於、等於、大於三堆，都避開了那個問題。這就是生成式 AI 的不確定性，每次寫出來的程式都不一樣。

審查員最後還提醒，兩份審查來自同一種審查員，差零點五到一分只是誤差，要看具體問題，不要只比分數。這個提醒很中肯。

成本這次你打開的是斜線 usage，不是斜線 cost，所以還是沒有數據。斜線 usage 看的是訂閱額度，斜線 cost 才是這個對話花了多少。

接下來是第四步，對應四之四節，讓四個 subagent 組成一個新聞團隊。一個負責搜尋今天台灣的十大新聞，一個負責研究 TIME 雜誌網站的版面風格，一個負責寫每則新聞的摘要，最後一個負責把這些做成網頁。

請照著做。

第一，請 Claude 在專案的點 claude 斜線 agents 裡，一次建立這四個 agent。聊天視窗有完整的提示詞，四個 agent 的說明都在裡面。

第二，一樣要結束 Claude Code 再重新開啟，讓新的 agent 載入。

第三，貼上書上的分工提示詞：先同時用新聞蒐集員和風格研究員，兩者都完成後，再用摘要員寫摘要，最後用網頁製作員完成網頁。

第四，觀察執行的順序。前兩個有沒有同時跑，後兩個有沒有等前面做完才開始。也看看每個 agent 交出了哪些檔案。

第五，打開做好的網頁，看看是不是有十則新聞、一則頭條，點標題能不能連到原始新聞，縮小視窗時版面會不會跟著調整。

第六，最後輸入斜線 cost，這次是 cost，不是 usage。

做完之後請回報四件事。第一，四個 agent 的執行順序。第二，產生了哪些檔案。第三，網頁看起來怎麼樣，連結能不能點。第四，總共花了多久、成本多少。
