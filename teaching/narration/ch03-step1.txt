互動教學。先判讀第二章第五步，接著進入第三章。

第五步有一個很重要的發現：這個實驗的對照組，在測試之前就被破壞了。

原因是你把我的說明整段貼給了互動模式的 Claude。它讀到規則要求檔名是 index 點 css 和 index 點 js，就在建立規則檔的同時，順手把 style 點 css 和 app 點 js 改名了，還自己開瀏覽器測試、commit 並推上去。等到你用 claude 減 p 問的時候，檔名早就符合了，所以兩種寫法都回答符合。我們本來想看的，是規則有沒有被讀到，這下就看不出來了。

這給我們一個教訓。教學說明是寫給你看的，不是寫給 Claude 執行的。整段貼給它，它就會把整個實驗做完，包括不該做的部分。之後的步驟，請你自己輸入指令，或只貼要給它的那一句提示詞。

另外還有三個觀察。

第一，兩次減 p 的回答，都是它自己先用指令把規則檔讀出來，再來判斷。所以這次還是無法證明規則是自動載入的。

第二，第二次減 p 發現 paths 裡 html 寫了兩次，就自己把它改成 html、css、js 三種，而且 commit 了。這和書上只套用在 html 的設計不同，是它自己擴大了範圍。

第三，互動模式的對話和減 p 的對話，同時在同一個資料夾裡改檔案、commit。互動模式那邊還發現多了一個不是它做的 commit。這正是你全域設定裡提醒的：不要讓兩個 session 共用同一個工作目錄。同一段時間，網頁伺服器也莫名其妙停掉了一次，可能和兩邊同時啟動伺服器有關，不過原因沒有查證。

第二章到這裡全部完成。

接下來是第三章，常用斜線命令。第一步要比較幾個看用量的命令，弄清楚為什麼它們的百分比都不一樣。

請在 web 資料夾的 Claude Code 裡，自己一個一個輸入，不要把這段說明貼給它。

第一，輸入斜線 context。看第三行，用量是用多少 tokens 當分母計算的。再看各個項目佔了多少，例如系統提示、工具、記憶檔、skill。

第二，看輸入框右下角顯示的 token 數字，和斜線 context 的總數比較。書上說，右下角的數字一定比較大，因為它包含了上一次的回覆，斜線 context 沒有。

第三，輸入斜線 cost，再輸入斜線 usage。斜線 usage 顯示的是你訂閱方案的額度，例如這五個小時和這一週用了多少，和上下文視窗是完全不同的東西，分母也不一樣。

第四，輸入斜線 stats，看你過去的使用統計。

第五，先隨便改一個檔案，例如在 web 底線 prd 點 md 最後加一行字，然後輸入斜線 diff，看它怎麼顯示改動。看完記得把改動還原。

做完之後，請把畫面貼過來，回報四件事。第一，斜線 context 用的分母是多少，用量百分比是多少。第二，右下角的數字和斜線 context 差多少。第三，斜線 usage 顯示的百分比是多少，和前面兩個有什麼不同。第四，佔用最多的是哪一個項目。
