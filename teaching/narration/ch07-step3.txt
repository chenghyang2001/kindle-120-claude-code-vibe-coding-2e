互動教學，第七章。先判讀第二步，再進行第三步。

第二步，Remote Control 確實連上了。記錄裡看得到你輸入了斜線 remote 減 control，這個對話被接到雲端，有一個 claude 點 ai 斜線 code 開頭的網址，手機就是透過它看到同一個對話的。而且它這次寫的 commit 訊息，最後還多了一行對話網址，這是遠端對話才有的標記。

後端照你的規則走了寫程式和驗證兩關，app 點 py 有兩百一十四行，三個測試都通過：正常下單、非法輸入被擋下、讀回 Excel 核對內容正確。它也主動建了 gitignore，把 orders 點 xlsx 排除，訂單資料不會被提交。啟動方式是先用 pip 安裝 requirements，再用 python 執行 app 點 py，打開一二七點零點零點一冒號五千就能看到網頁。

接著你要它把前端也接上後端，它也做了：分析菜單改呼叫真的 API、加了分機欄位、送出訂單會真的寫入 Excel，並用無頭瀏覽器跑完整個流程。

有兩件事要注意。

第一，前後端的整合，在這一步就已經完成了。可是書上的設計，是把整合留到下一步，交給雲端去做。所以下一步要換個方式練習，等一下會說明。

第二，它收尾關伺服器的時候，用了一個很危險的指令，等於把電腦上所有的 Python 程式都強制關掉，不只是它自己啟動的那一個。這次沒有造成損失，但如果你剛好有其他 Python 程式在跑，就會被一起關掉。而且它自己啟動的測試伺服器，其實還在背景佔著五千連接埠。

接下來是第三步，對應七之三節，Claude Code on the Web，也就是讓雲端的 Claude 接手開發。雲端碰不到你的電腦，只看得到 GitHub，所以要先把專案推上 GitHub。

因為整合已經在本機做完了，這次我們讓雲端從整合之前的版本重新做一次，再和本機的結果比較。

請照著做。

第一，用 gh repo create 把練習資料夾建成你 GitHub 上的公開 repo，並推上去。再把整合之前的那個 commit，也就是新增 Flask 後端那一個，另外建一個分支叫 before 減 integration，也推上去。聊天視窗和記事本裡有完整指令。

第二，用瀏覽器打開 claude 點 ai 斜線 code，第一次使用要連結 GitHub，並允許它存取這個 repo。

第三，選擇 k 一二零 ch 零七 practice 這個 repo，分支選 before 減 integration，輸入書上的提示詞：幫我整合前端小老鼠 index 點 html 和後端小老鼠 app 點 py。

第四，觀察雲端怎麼工作。它會在雲端的環境裡執行，完成後把結果推成 GitHub 上的一個新分支。

第五，回到電腦，用 git fetch 把雲端的分支抓下來，和本機剛才自己整合的版本比較，看看兩邊做法有什麼不同。

做完之後請回報三件事。第一，網頁版連 GitHub 的過程順不順利。第二，雲端完成後，新分支叫什麼名字。第三，雲端的整合和本機的整合，有什麼不一樣。
