互動教學，第四章。先判讀第二步，這一步兩輪都沒有照計畫走，但原因很有教育意義。

第一輪，你設了逃生門的環境變數，本來應該由主對話自己寫。結果它一開始就派了寫程式的 agent，花了七十三秒寫完六個檔案。原因是，逃生門只能讓 hook 不擋人，可是你的全域 CLAUDE 點 md 裡，還寫著主對話禁止自己寫程式檔的鐵律。模型讀到這條規則，自己就選擇派 agent 了，根本沒有走到會被 hook 擋的那一步。所以要改變模型的行為，光關掉 hook 不夠，寫在記憶檔裡的規則一樣有影響力。

第二輪有三個發現。

第一，它確實把三個 agent 建在專案的點 claude 斜線 agents 資料夾裡，這次沒有放到全域。

第二，你接著打斜線 clear，再用第二輪的提示詞，它卻說你指定的三個 agent 都不存在，改用了其他現成的 agent 代替，Python 交給 python pro，Go 和 JavaScript 交給 code writer。也就是說，在同一個對話裡新建的專案 agent，這時還沒有被載入。斜線 clear 只會清空對話，不會重新讀取 agent。最保險的做法，是建好之後結束 Claude Code 再重新開啟。

第三，三個 agent 確實是同一秒同時派出去的，各自只花了十六到三十四秒。可是整體花了一分五十二秒，比第一輪還慢。因為主對話派工之前，先想了一分鐘左右，最後還要等三次完成通知。這和舊電腦的結論一樣：題目這麼小，並行的好處會被固定開銷吃掉。

兩輪你都沒有看成本，所以成本這一題沒有數據。

接下來是第三步，對應四之三節，建立一個程式碼審查員，用獨立的上下文去比較兩輪寫出來的程式。書上比較的是 Rust，我們沒有寫 Rust，所以改成比較 Go。第一輪的檔案在資料夾最外層，第二輪的在 go 資料夾裡。

請照著做。

第一，請 Claude 在專案的點 claude 斜線 agents 裡，建立一個叫 personal code reviewer 的 agent，內容用書上的描述。聊天視窗有完整提示詞。

第二，這次一定要結束 Claude Code，再重新啟動。

第三，輸入小老鼠，看選單裡是不是出現了 personal code reviewer，還有上一步建的三個語言 agent。

第四，貼上比較的提示詞，請它用 personal code reviewer，分別審查最外層的 Go 程式，和 go 資料夾裡的 Go 程式，比較兩者的品質。

第五，做完之後輸入斜線 cost，這次記得看一下成本。

舊電腦的結果是兩邊幾乎打平，六點四分對六點五分，而且兩邊都有同一個問題：快速排序遇到大量重複的數值時，會退化得很慢。

做完之後請回報四件事。第一，重新啟動後，選單裡有沒有出現這四個 agent。第二，審查員給兩邊什麼評價，哪一邊比較好。第三，有沒有抓到同樣的快速排序問題。第四，成本多少。
