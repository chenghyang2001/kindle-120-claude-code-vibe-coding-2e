互動教學，第七章。先判讀第三步，再進行第七章最後一步。

第三步，雲端真的接手做完了。我把 GitHub 上的結果抓下來看，有三個發現。

第一，雲端沒有另外開新分支，而是直接把 commit 推到你指定的 before 減 integration 分支上。作者寫的是 Claude，commit 訊息最後一樣有對話網址的標記。

第二，雲端只改了 index 點 html，後端沒動，和本機一樣。它把分析菜單改成呼叫後端 API、加上分機欄位、送出訂單改呼叫 API、送出中停用按鈕防止重複送單。

第三，最有意思的是，雲端和本機的做法幾乎一模一樣。兩邊都寫了一個共用的 postJson 函式統一處理錯誤，也都想到用檔案方式直接打開網頁時，要自動改連一二七點零點零點一冒號五千。真正的差別只在細節：本機版把驗證失敗的提示，顯示在訂單列下方，還會把游標移到出錯的欄位；雲端版則是沿用彈出視窗。

雲端碰不到你的電腦，也沒有你的全域設定，卻寫出幾乎一樣的程式。這說明程式碼本身，加上清楚的提示詞，就足以讓結果很穩定。

接下來是第四步，對應七之四節，也是第七章最後一步。書上分成兩部分：第一部分是設定 Telegram 外掛，讓你從 Telegram 對 Claude 下指令；第二部分是新增用模型分析菜單的功能。

Telegram 外掛需要 Bot Token，和第六章一樣，這台電腦先跳過。不過第二部分不需要 Telegram，我們直接在終端機做。

請照著做。

第一，先把背景那個佔著五千連接埠的測試伺服器關掉。聊天視窗有指令。

第二，在練習資料夾啟動 claude，貼上書上的提示詞：寫一個程式，讓使用者在訂餐網頁輸入菜單網址之後，用 curl 抓網頁內容，再用 claude 減 p 分析，回傳專案指定的菜單 JSON 格式，即時更新訂餐網頁，顯示這間店的所有品項。

第三，做好之後啟動後端，打開網頁，貼上可不可的菜單網址，按分析菜單。分析會花一兩分鐘，耐心等。

舊電腦的結果是，花了兩分十五秒，分析出四十六個品項，每個品項都有杯型、甜度、冰塊、加料四組選項。

舊電腦也指出兩個安全疑慮，請你特別看它有沒有處理。第一，執行外部指令時用了 shell 等於 true，網址如果被塞進特殊符號，就可能執行任意指令。第二，伺服器會去抓使用者給的任何網址，有人可能拿它來存取公司內網，這叫做 SSRF。

做完之後請回報四件事。第一，它怎麼呼叫 curl 和 claude 減 p。第二，分析花了多久，出現幾個品項。第三，有沒有處理那兩個安全疑慮。第四，你的全域規則有沒有讓它走寫程式、驗證、審查的流程。
