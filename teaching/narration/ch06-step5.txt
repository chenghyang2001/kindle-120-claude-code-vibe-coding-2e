互動教學，第六章。先判讀第四步，再進行第五步。

第一，deny。它先去查官方文件，發現書上的網址已經轉到新的網址，照新文件寫出 JSON。被擋下時，Claude 看到的就是你指定的原因：這個專案不允許檔案被修改。檔案沒有被改，和舊電腦一樣。

第二，ask。你第一次按拒絕，Claude 收到的訊息是使用者不想繼續，它就停下來等你，沒有再試別的方法。你再要求一次，這次按允許，任務就刪掉了。它還提醒你，詢問畫面上的原因寫著不允許修改，可是按允許之後其實能改，文字和行為對不起來。這個觀察很中肯。

第三，updatedInput，結果和舊電腦完全相反。舊電腦的 Claude 被騙了，以為讀到的是設定檔。這次的 Claude 沒有被騙，原因是這個 hook 是它自己剛剛寫的，它知道讀檔工具會被導向 tasks 點 json，所以你要它讀設定檔時，它直接改用 cat 指令去讀，繞開了讀檔工具。

這帶出一個重點：updatedInput 騙得了不知情的模型，騙不了知情的模型。舊電腦是在一個全新的對話裡測的，模型完全不知道有這個 hook。如果要重現舊電腦的結果，必須在新對話裡測，而且不能讓它先看過設定檔。

另外有一個小插曲。它自己測試讀檔時，好幾次得到檔案沒有變化、請參考先前結果的回應。這是 Claude Code 為了省 token，對剛讀過的檔案不再重讀，所以那幾次其實根本沒有觸發到 hook，測試等於沒做。

最後你請它把讀檔的 hook 刪掉，它刪完之後實際讀一次設定檔，確認讀到的是設定檔本身，做得很確實。

接下來是第五步，對應六之五節的前半，用 if 條件讓 hook 更精準。前面的 hook 是一律攔截，這一步要讓它只在特定情況才出手。

目前的設定是所有修改都會問你，所以等一下它改設定檔時也會問，請按允許。

第一，貼上書上第一段提示詞，請它用官方的 if 條件語法，讓詢問只在修改 tasks 點 json 時才觸發。然後測兩個：幫我在 tasks 點 json 添加一個新任務，追蹤特定檔案，這個應該會問你。再來是：幫我在 todo 點 py 的最上方加入一行註解，追蹤特定檔案，這個應該不會問，直接改。

第二，貼上第二段提示詞，請它再建一個 hook，用 Bash 指令比對語法，攔截 rm、sudo、chmod 開頭的危險指令。然後測兩個：幫我用 Bash 指令刪除 delete 點 txt，這個應該被擋。再來是：幫我用 Bash 指令建立一個檔案 add 點 txt，這個應該可以。

舊電腦的結果是，rm 被擋、delete 點 txt 還在，建立 add 點 txt 成功。

做完之後請回報三件事。第一，它寫出來的 if 條件長什麼樣子。第二，四個測試各有沒有照預期問你、擋下或放行。第三，被擋下的時候 Claude 有沒有改用其他方法刪檔案。
