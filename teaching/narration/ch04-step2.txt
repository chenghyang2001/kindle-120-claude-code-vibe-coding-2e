互動教學，第四章。先判讀第一步，這一步和書上幾乎完全相反，很值得仔細看。

第一個不同，斜線 agents 的建立精靈已經被拿掉了。你輸入斜線 agents，畫面只告訴你：請直接叫 Claude 幫你建，或是自己編輯點 claude 資料夾裡的 agents 檔案。書上那個一步一步選範圍、選工具的畫面，這個版本已經沒有了。

第二個不同，它把翻譯員建在使用者層級的全域資料夾，而不是這個專案裡。理由是它覺得翻譯員是通用工具。結果就是，連我這個教學對話，現在也看得到這個翻譯員。而且你的全域資料夾會用 git 同步，如果之後被提交，其他電腦也會有。如果你只想在這個練習用，可以請它把檔案搬到專案的點 claude 斜線 agents 資料夾。

第三個不同，也是最重要的。第一句提示詞沒有指名，主對話卻直接把工作交給了翻譯員。舊電腦和書上都是主對話自己翻。原因在於，它幫翻譯員寫的說明裡，放了很多觸發詞，像是翻成繁中、翻譯這份文件。主對話看到說明這麼符合，就自己決定交出去。所以會不會自動交給 subagent，關鍵在 agent 的說明怎麼寫。

第四，你沒有先輸入斜線 clear，就直接打第二句。主對話發現檔案剛剛已經翻過了，原檔也沒有改，就沒有再翻一次。所以兩句提示詞的比較這次沒有做成。第一句總共大約二十六秒，其中翻譯員自己跑了大約十二秒。

接下來是第二步，對應四之二節，比較一個人寫和多個 subagent 同時寫，哪一個比較快。

書上是七種語言、各五種排序法，一共三十五支程式。這太大了，舊電腦也把題目縮小成三種語言、各兩種排序法，我們照舊電腦的規模做，方便對照。

但是有一個問題。你的全域 hook 不准主對話直接寫程式檔，第一輪就算你要它自己寫，它也會被迫派 agent，這樣就沒有辦法比較了。所以第一輪要用你自己設計的逃生門，在啟動前設定 FORCE 底線 DIRECT 底線 WRITE 等於一。這個設定只對這一次啟動有效，關掉就失效。

請照著做。

第一，結束目前的 Claude Code。在 PowerShell 輸入：錢字號 env 冒號 FORCE 底線 DIRECT 底線 WRITE 等於一，然後再輸入 claude。聊天視窗有完整指令。

第二，貼上第一輪的提示詞：用 Python、Go、JavaScript 寫出 bubble 和 quick 兩種排序法，每個程式獨立存檔，不用編譯執行和測試，並計算花了多少時間完成。記下時間，再用斜線 cost 看成本。

第三，結束 Claude Code，把剛剛那個環境變數清掉，聊天視窗有指令。重新啟動 claude。

第四，請 Claude 在這個專案的點 claude 斜線 agents 資料夾裡，建立三個 agent，分別負責 Python、Go 和 JavaScript。記得強調要放在專案裡，不要放全域。

第五，輸入斜線 clear，然後貼第二輪的提示詞：請分別用這三個 agent，寫出 bubble 和 quick 兩種排序法，只要寫出來存檔，不用編譯執行和測試，並計算花了多少時間完成。

舊電腦的結果是，一個人寫十六秒，三個 subagent 同時寫九秒，可是成本多了八成五。題目太小的時候，啟動 subagent 的固定開銷，會把並行省下的時間吃掉。

做完之後請回報三件事。第一，兩輪各花多久、成本各多少。第二，第二輪三個 agent 是不是同時跑的。第三，三個 agent 檔案放在哪裡。
