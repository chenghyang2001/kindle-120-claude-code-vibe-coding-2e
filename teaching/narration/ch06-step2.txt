互動教學，第六章。先判讀第一步，再進行第二步。

第一步有一個和書上很不一樣的地方：hook 改了之後，馬上就生效了，不用重新啟動。Claude 寫好設定檔之後，自己執行了一行無害的 echo 測試，立刻就被擋下來。你後來兩次手動改設定檔，也都沒有重開，新的設定一樣馬上生效。所以新版的 Claude Code 會自動偵測設定檔的變化。

Claude 也很聰明。它知道 hook 一生效，自己就不能再執行任何指令，所以把寫設定檔、檢查 JSON 格式、commit 合在同一個指令裡一次做完。

第一次測試，被擋下來了，tasks 點 json 沒有改，Claude 只看到沒有錯誤輸出這句話，和舊電腦一樣。被擋下之後它也說得很清楚：我不會用其他方法繞過它，然後給你兩個選擇。這點也和舊電腦一樣守規矩。

第二次測試，你跟它說 hook 已經移除了，但其實你是把它改成 PostToolUse。Claude 修改成功之後跳出錯誤，它馬上判斷出來：hook 沒有被刪掉，只是改成工具執行完才觸發，所以擋不住，只會在事後回報錯誤。結果和書上一樣，PostToolUse 擋不住。

第三次測試有一個小狀況。你把退出代碼改成一，但沒有改回 PreToolUse，所以實際測的是 PostToolUse 加退出代碼一，和原本設計的 PreToolUse 加退出代碼一不同。檔案一樣被改了，而且這次 Claude 連錯誤都沒看到，因為退出代碼一不會把錯誤傳給模型。結論還是一樣：只有退出代碼二會阻擋。另外，Claude 還主動更正了自己上一則回覆裡說錯的任務狀態，這是很好的習慣。

全程也沒有出現你全域那個提醒還沒 commit 的 hook，代表 setting sources 參數確實把全域 hook 排除掉了。

接下來是第二步，對應六之二節的後半：在用退出代碼二阻擋之前，先輸出阻擋的原因，看看 Claude 會不會知道為什麼被擋。

請照著做。

第一，先把 tasks 點 json 還原。在 Claude Code 裡輸入驚嘆號 git checkout 空格 減減 空格 data 斜線 tasks 點 json。

第二，貼上書上的提示詞，請它修改 hook，在用退出代碼二阻擋之前，先透過標準錯誤輸出說明原因：禁止修改，此專案的 hook 已封鎖所有檔案編輯操作。目前設定是 PostToolUse 加退出代碼一，請注意看它有沒有一起改回 PreToolUse 和退出代碼二。

第三，輸入測試提示詞：幫我在 tasks 點 json 添加第四個任務，測試 hook 運作。

觀察重點是，這次 Claude 看到的不再是沒有錯誤輸出，而是你寫的那段原因。舊電腦的結果是，檔案沒有被改，Claude 也在回覆裡引用了這段原因。

做完之後請回報三件事。第一，它改出來的設定檔長什麼樣子。第二，tasks 點 json 有沒有被改。第三，Claude 的回覆裡有沒有提到你寫的原因。
