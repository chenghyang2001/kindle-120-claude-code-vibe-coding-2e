互動教學。先判讀第八章第四步，再整理第八章四種開發方式的比較，最後進入第九章。

第四步，grill me dev 運作得完全照書上的設計。你第一次沒有附上題目就執行，它看了資料夾，發現什麼都沒有，就從專案目標開始問。第二次附上開發一個數獨 python app，它就從用途、介面、解題方式、難度分級、專案結構、出題時會不會卡住畫面，一路問到交付流程，總共十六題。每次只問一題，每題都附上選項比較表和建議答案。你每一題都回答照建議，問答花了大約十分鐘。

接著它分四批開發，每一批做完就更新規格書，最後用 tkinter 完成，不需要任何外部套件，三百九十個測試通過，Python 三點一二和三點一四都測過，也實際開了視窗截圖。開發大約四十七分鐘。最後你說到這裡就好，所以書上的新增暫停功能和每日挑戰，這次沒有再做。

有一件事要提醒你。它發現第二批的 commit 不是它自己做的，是某個它不認得的程序，在審查還沒完成時就 commit 並推上去了。內容沒有問題，但原因它沒有查到。可能是某個 agent 自己 commit 了，也可能是你某個自動化設定，之後值得留意。

現在把第八章四種方式放在一起比較。第一種直接對話，做成網頁，最快，大約十四分鐘，而且因為是 HTML，不受你的程式碼規則影響。第二種 PRD，用 PySide6，大約四十分鐘，審查抓到中等難度名不副實的問題。第三種 subagent，用 CustomTkinter，大約三十分鐘，主對話把工作分成四個階段，該平行的平行。第四種 grill me，用 tkinter，先花十分鐘把十六個決策問清楚，再花四十七分鐘開發。

舊電腦最大的問題是 subagent 版高難度出不了題，這次四個版本都沒有這個問題。這次最大的差別反而來自你的全域規則：只要寫 Python，就會走寫程式、驗證、審查的流程，品質高但時間長很多。

接下來是第九章，最後一章，把 YouTube 影片轉成投影片。第一步對應九之一節：先放 Karpathy 的四條行為準則到 CLAUDE 點 md，再用 Plan 模式，讓 Claude 用選單一題一題訪談你，最後寫出規格文件。

請照著做，指令都在記事本裡。

第一，建立練習資料夾 k 一二零 ch 零九 practice，把 Karpathy 版的 CLAUDE 點 md 複製進去，git init，啟動 claude。

第二，按 Shift 加 Tab 切到 plan 模式。

第三，貼上書上的需求提示詞。最後一句很關鍵：請先用 AskUserQuestion 工具詳細詢問我，不要問顯而易見的問題，要挖掘我可能沒想到的難點。

第四，回答它的訪談。這一步只做到規格文件為止，先不要讓它開始寫程式，下一步才用斜線 goal 來實作。

有一個值得觀察的地方。Karpathy 的規則說簡單優先，不要為不可能發生的情況寫錯誤處理。可是你的全域規則要求一定要寫錯誤處理，還要派寫程式和驗證的 agent。兩邊衝突的時候，看它怎麼取捨。

舊電腦跑書附範例時，因為範例鎖定 Python 三點九，新版的 yt dlp 已經不支援，結果抓不到 YouTube 影片。這次看看它會不會一開始就避開這個坑。

做完之後請回報三件事。第一，訪談問了幾題，哪幾題是你沒想到的。第二，規格文件選了哪些技術。第三，它怎麼處理兩套規則的衝突。
