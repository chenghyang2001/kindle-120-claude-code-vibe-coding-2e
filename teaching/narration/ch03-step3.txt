互動教學，第三章。先判讀第二步，再進行第三章最後一步。

第二步，斜線 model 你看完沒有切換，目前是 Opus 五點五，也是預設值。斜線 config 和斜線 permissions 你都打開看過再關掉，記錄裡只寫著已關閉，沒有留下內容，所以允許和拒絕各有幾條，我沒辦法幫你對照。

狀態列這一題很成功。它派了一個專門設定狀態列的 agent，只寫進這個專案的 settings 點 local 點 json，全域設定完全沒有動，我檢查過全域設定檔今天早上之後就沒改過。這個設定檔也已經被 gitignore 排除，不會被提交，也不會同步到其他電腦。

和書上不同的地方是，書上通常會產生一支獨立的腳本檔，這次它把整段指令直接寫成一行，放在設定檔裡，用 jq 讀取 Claude Code 傳進來的資料。它自己用模擬資料測過，輸出是資料夾名稱、web 分支、ctx 百分之十八。第一次回覆之前還沒有用量數字，那時只會顯示資料夾和分支。

接下來是第三步，比較本機排程和雲端排程，也就是斜線 loop 和斜線 schedule。

一樣請你自己輸入。

第一，輸入斜線 loop，空一格，一 m，再空一格，接一句話：回報現在的時間和 git status 的摘要，只要一行。意思是每一分鐘做一次。讓它跑兩三次，觀察它是怎麼被叫醒的。

第二，看夠了就按 Esc，或直接告訴它停止。

第三，輸入斜線 schedule，看看雲端排程的畫面。這一步只要看，先不要建立。雲端排程在 Anthropic 的伺服器上跑，你的電腦關機也會照樣執行。但它碰不到你電腦裡的檔案，也連不到一二七點零點零點一這種本機網址，只能處理 GitHub 上的 repo。而且每次執行都會用掉你的訂閱額度。

比較一下兩者。斜線 loop 在本機跑，可以碰到你所有的檔案，但對話一關掉就停了。斜線 schedule 在雲端跑，電腦關機也不受影響，但只看得到 GitHub 上的東西。

做完之後請回報三件事。第一，loop 跑了幾次，每次間隔多久，有沒有準時。第二，你怎麼讓它停下來的。第三，schedule 的畫面上有哪些選項，你帳號裡已經有沒有排程。
