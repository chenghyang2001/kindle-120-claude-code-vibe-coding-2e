互動教學，第八章第三步。PRD 的雙星號修正你決定跳過，我已經記在交接文件裡，之後想補可以再做。

這一步對應八之四節，同一份 PRD，這次改成讓四個專門的 subagent 分工：遊戲邏輯工程師、介面工程師、資料工程師和視覺設計師，各自負責一塊，再組合成一個遊戲。

請照著做，所有指令都在記事本裡，可以直接複製。

第一，建立練習資料夾 k 一二零 ch 零八 practice 減 sub，把上一步用過的 CLAUDE 點 md 和 PRD 點 md 複製進去，git init，啟動 claude。

第二，請 Claude 在專案的點 claude 斜線 agents 裡，建立四個 agent，四段角色說明都是書上的原文。

第三，記得第四章學到的：新建的 agent 要重新啟動才會載入。所以先斜線 exit，再重新啟動 claude，輸入小老鼠確認選單裡有這四個 agent。

第四，輸入書上的提示詞：請四位 agent 依照各自的職責，協作完成小老鼠 PRD 點 md 中的數獨專案。

第五，做好之後用 uv run python main 點 py 試玩。如果遇到按鈕和文字重疊，或是高難度出題太慢，就用書上的修改提示詞請它修。

這一步有三個觀察重點。

第一，你的全域規則要求主對話寫程式時派寫程式的 agent。看看這次它會派你建的這四位，還是改派 code writer，兩種規則會不會打架。

第二，四位 agent 是同時開工，還是有先後順序。照理說介面工程師要等遊戲邏輯的模組做好，才能串接。

第三，四個人各寫各的，最後串起來會不會對不上。

舊電腦的結果很值得對照：subagent 版用 pygame 做，簡單和中等出題很快，但困難和專家在一百八十秒內連一題都出不來。原因是出題器每次都要做完整的技巧分級。這正好就是書上最後那句修改提示：高難度題目生成過慢。

做完之後請回報四件事。第一，主對話派了哪些 agent、順序怎樣。第二，用了哪個 GUI 套件、花了多久。第三，困難和專家出題快不快。第四，有沒有按鈕和文字重疊。
