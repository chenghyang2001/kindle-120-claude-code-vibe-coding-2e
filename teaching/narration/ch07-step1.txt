互動教學。先判讀第六章第六步，接著進入第七章。

第一，外部程式。它把判斷程式放在點 claude 斜線 hooks 資料夾，叫 bash guard 點 py，用 uv 執行。這次照你的規則走了寫程式、驗證、審查三關，花了大約十一分鐘。

最精彩的是審查那一關。審查員用 Git Bash 實際試了很多種繞過的寫法，例如把 rm 包在括號裡、在前面加上 command 或 env、把 rm 寫成大寫，還有用 bash 減 c 包起來。這些寫法都真的把檔案刪掉了，hook 卻全部放行。退回修正之後，程式多了這些情況的判斷，自帶四十五個測試案例，審查員複審才通過。這說明用字串比對來擋危險指令，比想像中容易被繞過。

兩個測試都照預期。mv 搬移跳出詢問，你允許後搬好了。rm 刪除被擋下，它也再次說明不會改用其他方法繞過。

第二，prompt 型 hook。它設好了 Opus 五點五，timeout 十五秒，prompt 照你的要求先留空。它也幫你產生了一段很完整的 prompt，但是只貼在對話裡，沒有寫進設定檔。所以實際測試的時候，prompt 是空的。

有趣的是，prompt 空白，模型還是自己判斷了。它說沒有明確的條件，所以當成安全檢查，cat 點 env 會印出整個檔案，裡面通常有 API 金鑰，所以拒絕。查看 todo 點 py 則放行。

第三，最重要的發現，和舊電腦一模一樣。cat 點 env 被 prompt 型 hook 擋下之後，Claude 最後一句話都沒有說，回覆是空的。你只看得到錯誤訊息，看不到它的說明。這是 prompt 型 hook 目前的行為，記住它，以後遇到 Claude 突然不說話，可能就是被這種 hook 擋了。

第六章到這裡完成，Telegram 那一步之後再補。

接下來是第七章，遠端遙控和雲端協作。第一步對應七之一節，用 Claude Code Desktop，也就是桌面版應用程式，做訂餐系統的前端，然後用它內建的 Preview 預覽網頁。我檢查過，這台電腦已經裝了 Claude 桌面版。

請照著做。

第一，在 workspace 底下建立一個空的練習資料夾，叫 k 一二零 ch 零七 practice，進去之後執行 git init。

第二，打開 Claude 桌面版，切到 Code 分頁，選擇剛剛建立的資料夾。

第三，貼上書上的提示詞，請它建立旗標訂餐系統的前端頁面，有菜單網址輸入框、分析菜單按鈕、品項卡片、備註欄和送出訂單按鈕，最後開 Preview 讓你確認。聊天視窗有完整提示詞。

第四，在 Preview 裡實際操作看看。因為還沒有後端，按分析菜單應該不會有真的資料，看它怎麼處理。

觀察重點是，桌面版和終端機版有什麼不一樣，尤其是 Preview 怎麼呈現，能不能直接在裡面點按鈕。

做完之後請回報三件事。第一，桌面版的操作畫面和終端機有什麼不同。第二，Preview 有沒有自動打開，網頁長什麼樣子。第三，按分析菜單時發生什麼事。
