互動教學，第二章。先判讀第三步，再進行第四步。

第三步我一樣是看對話記錄，再加上實際檢查檔案。

第一，accept edits 模式。你在這個模式下要求改成紅色，它直接改了檔案，沒有再問你。因為只改一行，你的 hook 也沒有要求它派 agent。它還自己重新產生 PDF、轉成圖片確認是紅色，然後打開給你看。Shift 加 Tab 出現了哪幾種模式，記錄裡看不到，這一題請你自己記得就好。

第二，rewind，這是這一步最重要的發現。我檢查過，add 底線 watermark 點 py 第一百四十三行已經改回灰色，所以程式碼確實還原了。可是 sample 底線 wm 點 pdf 裡面，浮水印還是紅色的。原因是 rewind 只會還原 Claude 用編輯工具改過的檔案。PDF 是它用指令執行程式產生的，rewind 不會追蹤，也不會還原。官方文件也是這樣說明的。所以 rewind 不能取代 git，用指令產生或刪除的檔案，要靠 git 或自己重新產生。這個 PDF 只要重新執行一次程式就會變回灰色。

第三，init。它把 CLAUDE 點 md 整個重寫了，從九行變成五十九行。三條 uv 規則都還在，還多了一條：臨時用的套件用 uv run 減減 with，不要寫進專案設定。新增的內容有常用指令、處理流程，以及八條改程式時不能破壞的規則，每一條都是這次審查踩過的坑。這比書上的 init 結果豐富很多，因為它把前面三十分鐘的審查經驗也寫進去了。

第四，git。你另外要求推上 GitHub，它照你全域設定的習慣建了公開的版本庫。commit 裡有六個檔案：兩支程式、CLAUDE 點 md、pyproject、uv 點 lock，還有 gitignore。gitignore 排除了虛擬環境、快取資料夾和所有 PDF，也把你本機的 settings 點 local 點 json 排除了。

接下來是第四步，對應二之三節。要用 git worktree 開一個獨立的工作目錄，在 plan 模式下，照一份需求文件做出網頁版。

worktree 的好處是，網頁版在另一個資料夾、另一個分支開發，不會弄亂原本已經可以用的命令列版。

請照著做。

第一，在練習資料夾用驚嘆號執行 git worktree add，在旁邊建一個叫 k 一二零 ch 零二 practice 減 web 的資料夾，分支名稱叫 web。聊天視窗有完整指令。

第二，結束目前的 Claude Code，在新的終端機切到那個 web 資料夾，輸入 claude 啟動。

第三，把書上的 web 底線 prd 點 md 存進這個資料夾。聊天視窗有完整內容。你可以直接請 Claude 幫你建這個檔案。

第四，按 Shift 加 Tab 切到 plan 模式，然後輸入：請依照 web 底線 prd 點 md 實作網頁版。plan 模式下它只會讀檔和規劃，不會改任何檔案。請看它列出的計畫，確認之後再同意執行。

提醒一下，你的 hook 這次一樣會要求它派 agent。如果不想等三十分鐘，可以告訴它這次是中等複雜度，不要派審查。

第五，做好之後，執行 uv run add 底線 watermark 點 py，不要加任何參數。照 PRD 的規定，它應該啟動網頁伺服器，使用五零五零連接埠。用瀏覽器打開，實際上傳一個 PDF 試試看。

舊電腦跑書附範例時發現三件事，可以拿來對照。一，網頁背景會跟著系統的深淺色主題變化，淺色模式下並不是高科技感。二，上傳之前，輸出檔名欄位確實是不能輸入的。三，API 的浮水印文字欄位名稱傳錯時不會報錯，會直接用預設的 Confidential。

做完之後請回報四件事。第一，plan 模式列出的計畫大概有哪些步驟。第二，網頁版面和 PRD 的圖一不一樣。第三，上傳 PDF 之後能不能下載加了浮水印的檔案。第四，hook 這次問了什麼，你怎麼回答。
