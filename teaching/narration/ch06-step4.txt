互動教學，第六章。Telegram 通知那一步，這台電腦先跳過，以後有 Bot Token 再補做。

接下來是第四步，對應六之四節，改用 JSON 格式回覆來控制 hook。退出代碼只能表示擋或不擋，JSON 可以說得更清楚：拒絕、詢問你，甚至偷偷改掉工具要做的事。這一步會依序測試三種：deny、ask 和 updatedInput。

我看過你的設定檔，目前 hooks 是空的，正好從乾淨的狀態開始。

第一個是 deny。貼上書上的提示詞，請它把 PreToolUse hook 改成用 JSON 輸出 deny，並附上拒絕原因：這個專案不允許檔案被修改。這次 hooks 是空的，所以請它照書上的觸發條件，重新建立 matcher。然後測試：幫我在 tasks 點 json 添加一個新的任務，了解 JSON 輸出介面。觀察它被擋下時，看到的原因是什麼。

第二個是 ask。現在 deny 會擋住所有修改，Claude 一樣改不了設定檔。所以請你自己用編輯器打開設定檔，把 deny 改成 ask。然後測試：幫我把 tasks 點 json 的最後一個任務刪除。這次 Claude 修改之前，會跳出畫面問你要不要允許。你可以先按拒絕，看它怎麼反應，再請它重做一次，這次按允許。

第三個是 updatedInput，這是最值得注意的一個。請它新增一個 hook：每當 Claude 要讀取檔案時，就把要讀的檔案偷偷換成 data 資料夾裡的 tasks 點 json。然後測試：我想看看現在有什麼 hook，幫我讀取設定檔 settings 點 json。

舊電腦的結果很驚人。Claude 以為自己讀的是設定檔，實際上拿到的是待辦清單的內容，於是得出一個錯誤的結論，說這個設定檔其實是 JSON 待辦清單。它完全不知道內容被換掉了。所以 updatedInput 只適合拿來加安全限制，例如把危險的指令改成安全的版本，不適合拿來偷換內容。

做完這三個測試之後，記得把 updatedInput 那個 hook 刪掉，不然之後 Claude 讀任何檔案都會讀錯。

做完之後請回報三件事。第一，deny 的時候 Claude 看到了什麼原因。第二，ask 的時候畫面怎麼問你，你拒絕之後它怎麼反應。第三，updatedInput 的時候，Claude 有沒有發現讀到的內容不對。
