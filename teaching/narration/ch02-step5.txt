互動教學，第二章。先判讀第四步，再進行第二章的最後一步。

第四步，網頁版做出來了，而且我自己連到五零五零連接埠，確認網頁是正常的。

先講和書上不同的地方。

第一，plan 模式不是你按 Shift 加 Tab 進去的。你把整段說明貼過去之後，Claude 自己呼叫了進入 plan 模式的工具，寫好計畫，請你核准之後才開始做。結果一樣，但觸發的方式不同。

第二，它先問複雜度，你選了中等、不派審查。所以這次只花了大約八分鐘，第二步花了三十三分鐘。

第三，技術選擇不同。書附範例用的是 FastAPI，這次只用 Python 內建的標準函式庫寫伺服器，沒有加任何新套件。前端拆成了 html、css、js 三個檔，還有一張自己畫的 SVG 背景。舊電腦的書附範例，前端全部塞在一個檔案裡。另外，這次的背景固定是深色的高科技風，不會跟著系統主題變色。

第四，它用 Chrome 擴充功能自己打開瀏覽器，上傳 PDF、按開始、檢查下載連結，七頁都正確，最後 commit 並推上 web 分支。

還有兩件事要提醒。一，你的全域 Stop hook 每一輪都在提醒有沒 commit 的改動，在 agent 還沒跑完的時候，這只是雜訊。二，五零五零的伺服器現在還在背景執行，用完記得關掉。

最後要承認一個我的錯誤。我上一步給你的 PRD，少了書上的第六條：上傳和處理好的 PDF 要放在 cache 資料夾，而且不要提交到儲存庫。這是我節錄原文時截斷的。還好這次它把檔案放在系統暫存資料夾，也沒有提交進去，結果算是符合精神，但放的位置和書上不同。

接下來是第五步，對應二之四節，也是第二章最後一步。這一步要比較兩種寫規則的方法，順便練習非互動模式，也就是 claude 減 p。

規則內容是：網頁要拆成 html、css、js 三個檔，而且 css 要叫 index 點 css，js 要叫 index 點 js。目前的前端，檔名是 style 點 css 和 app 點 js，正好不符合，可以拿來測試規則有沒有被讀到。

請在 web 資料夾照著做。

第一，建立 front 底線 end 資料夾裡的 CLAUDE 點 md，內容是書上的網頁標準。這是第一種寫法，把規則放在子資料夾裡。

第二，在終端機輸入 claude 減 p，後面接一段問題：前端檔案有沒有符合規範？只回答，不要修改任何檔案。減 p 的意思是問完一次就結束，不會進入對話畫面。觀察它有沒有發現檔名不符合規定。

第三，把 front 底線 end 裡的 CLAUDE 點 md 刪掉，改成第二種寫法。在點 claude 資料夾裡建立 rules 資料夾，裡面放 web 點 md。開頭有一段 paths 設定，表示這條規則只套用在 html 檔案上。

第四，再用 claude 減 p 問一次同樣的問題，比較兩次的回答。

第五，最後再用 claude 減 p 請它照規則把檔案改名，並修正 html 裡的引用。改好之後，啟動伺服器，確認網頁還能正常使用。

做完之後請回報三件事。第一，兩種寫法下，它有沒有都發現檔名不符合。第二，兩次回答有什麼不同。第三，改名之後網頁還能不能用。
