互動教學，第二章。先判讀第二步，再進行第三步。

第二步的結果，我讀了對話記錄，也自己打開了輸出的 PDF 量過。結論是功能完全正確，但過程和書上差非常多。

先講結果。它照 CLAUDE 點 md，用 uv init 和 uv add 建專案，裝了 pypdf 和 reportlab，沒有用 pip。它自己產生了測試 PDF，sample 點 pdf 有五頁，分別是 A4、Letter、A3 橫向、A5，還有一頁三百乘八百的窄長頁。另外還做了一份七頁的特殊測試檔，有旋轉九十、一百八十、兩百七十度的頁面，還有一頁一百乘一千的極窄頁。我逐頁檢查過，十二頁全部都有 Confidential。最後它也用預設的 PDF 閱讀器，把結果打開給你看。舊電腦的書附範例只有三頁，這次的測試範圍大很多。

再講過程，這是最值得比較的地方。書上只要一個提示詞，幾分鐘就完成。這次因為你的全域 hook，它先問你複雜度，然後依序派寫程式、驗證、審查三種 agent。結果總共跑了五輪驗證、四輪審查，花了大約三十三分鐘。程式從一開始的一百七十四行，長到四百一十行。書附範例的主程式只有一百二十一行。

審查每一輪都抓到真的會出錯的問題。例如書籤和連結會遺失、共用內容的頁面會疊上兩層浮水印、加密檔的錯誤訊息看不懂、兩百頁的檔案輸出後大了七倍。這些書附範例幾乎都沒有處理。

所以這是一個取捨。書上的做法快，適合先做出能用的東西。你的規則慢，但品質高很多。如果只是練習，或者做一次性的小工具，三十分鐘可能太久了。這時你可以告訴它這是簡單等級、不要派審查，就會快很多。

接下來是第三步，還是對應二之二節。這一步要練習三個功能：權限模式、回到上一個狀態，還有用 init 更新 CLAUDE 點 md。最後再用 git 存檔。

請在練習資料夾的 Claude Code 裡照著做。

第一，按 Shift 加 Tab，連按幾次，看畫面下方的模式名稱怎麼變化。找到 accept edits，也就是自動接受編輯的模式，停在那裡。

第二，在這個模式下，請它做一個很小的修改。例如說：把浮水印的顏色改成紅色，只改一行就好。觀察它改檔案的時候，有沒有再問你同意。因為只改一行，你的 hook 應該不會要求它派 agent。

第三，打開 sample 點 pdf 確認變成紅色之後，我們要把它復原。書上稱這個功能叫 checkpoint。現在的版本可以輸入斜線 rewind，或是連按兩次 Esc 鍵。選擇改顏色之前的那個時間點，並選擇連程式碼一起還原。然後用驚嘆號 git diff 或直接打開檔案，確認顏色真的改回來了。

第四，輸入斜線 init。它會掃描整個專案，更新 CLAUDE 點 md。請注意看它有沒有保留你原本寫的三條 uv 規則。

第五，請它幫你建立 git 版本庫，並且做第一次 commit。注意看它有沒有建立 gitignore，把點 venv、快取資料夾和測試產生的 PDF 排除掉。

做完之後，請直接把畫面貼過來，回報五件事。第一，Shift 加 Tab 出現了哪幾種模式。第二，accept edits 模式下改檔案有沒有問你。第三，rewind 之後程式碼有沒有真的還原。第四，init 之後 CLAUDE 點 md 多了什麼，uv 規則還在不在。第五，git commit 裡包含了哪些檔案。
