互動教學。先判讀第七章第四步，接著進入第八章。

第四步，菜單分析做得比書上和舊電腦都完整很多，花了大約二十分鐘，驗證跑了三輪，審查跑了兩輪。

先看結果。可不可的網址，最後版本三十秒分析出八十五個品項，中杯和大杯拆成兩個品項，選項也拆成半糖少冰這種短選項，可以直接在下拉選單選。舊電腦是兩分十五秒、四十六個品項。下單後也正確寫進 Excel。

它的做法是：先用 curl 抓網頁，轉成純文字，再交給 claude 減 p 分析。而且它特別做了三件很聰明的事。第一，呼叫 claude 減 p 時把所有工具關掉，就算網頁裡藏了惡意指令，也不會被執行。第二，執行前把 API 金鑰的環境變數移除，確保走你的訂閱額度，不會扣 API 費用。第三，同一個網址十分鐘內重複查詢，直接用快取，不再呼叫 claude。

再看舊電腦提出的兩個安全疑慮，這次都處理了。第一，執行外部指令時，用的是參數清單，不是 shell 等於 true，所以網址裡的特殊符號沒辦法變成指令。第二，SSRF 處理得非常徹底：檢查網址是不是內網位址，轉址的時候每一跳都重新檢查，還把連線鎖定在檢查過的 IP，防止 DNS 被中途換掉。另外，後端也改成只接受本機的請求，外部網站沒辦法借你的電腦去消耗 claude 額度。

代價是，不能再直接雙擊打開 index 點 html，一定要用一二七點零點零點一冒號五千開。

有一個小插曲。最後你要它推上 GitHub，它發現 repo 已經存在，就說應該是之前某個自動化流程建的。其實那是你在第三步自己用 gh repo create 建的。它不記得這件事，就自己猜了一個原因。這提醒我們，模型對自己不知道的事，有時會編一個說法，判讀時要留意。

第七章到這裡完成，Telegram 外掛之後再補。

接下來是第八章，用數獨遊戲比較四種開發方式。第一步對應八之二節，最直接的方式：只靠對話，一句話就讓它做，再一次丟出八項改良。

請照著做。

第一，在 workspace 底下建立空資料夾 k 一二零 ch 零八 practice 減 chat，進去 git init，再啟動 claude。

第二，只輸入一句話：請幫我製作一個數獨遊戲 app。觀察它選了什麼技術，是網頁、還是 Python 桌面程式，以及有沒有先問你問題。

第三，試玩一下，然後貼上書上的八項改良提示詞，包括分四個難度、加快出題、首頁、上一步和暫停、自動存檔、背景風格、遊玩紀錄，還有每日挑戰。聊天視窗和記事本有完整提示詞。

這段提示詞的第一項有一句很重要的話：請先告訴我你認為的 X wing 與 swordfish 是什麼。這叫做對齊術語。先確認它理解的和你想的一樣，再讓它動手，可以避免做出來才發現誤會。

提醒一下，你的全域規則會讓它走寫程式和驗證的流程，八項改良的規模不小，可能要花比較久。如果想快一點，可以回答中等、不派審查。

舊電腦的書附範例，這種方式做出來的是純網頁版。

做完之後請回報四件事。第一，一句話時它選了什麼技術。第二，它怎麼解釋 X wing 和 swordfish。第三，八項改良都做到了嗎。第四，總共花了多久。
